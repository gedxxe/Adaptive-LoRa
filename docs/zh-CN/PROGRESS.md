| 结论 | 核对方式 |
|---|---|
| 自适应镜像发送恰好 32 字节的 ASCII 样本 | 主机测试解码两个样本，并核对每次重传的帧字节一致。 |
| 五个 SF9 加三个 SF7，或两个 SF10 加六个 SF7，均可交付 32 B 样本 | 使用模拟无线传输运行实际状态机。两个 SF10 的测试覆盖重传和拒绝第三个节点升档。 |
| 两个 SF10 的组合在帧尾预留之外还剩 77.408 毫秒 | 模型计算。真实交付和无线时序仍需实测。 |
| 控制链路丢失时 Client 在 SF9 等待 | SF10 成功交付后模拟断联。收到新的有效 Beacon 和 Grant 后恢复交付。 |
| 重新加入的 Client 可恢复已确认的 SF，并保留其他节点的预留 | 模拟无线传输覆盖离线额度释放、延迟回执和 SF10 额度有限的情况。 |
| 降档未确认时回到此前 SF | 模拟首传失败、ACK 回执缺失以及试用中断联。 |
| Request 余量偏乐观而 DATA 持续丢失时，可以从 SF8 恢复到 SF10 | 使用模拟无线传输运行实际状态机，第二个 Client 每帧均成功交付。 |
| Grant 反复丢失时，不保留未确认的较高 SF | 三种规则均回退。在已有两个 SF10 预留的八节点测试中，第三个 Client 的恢复试用被拒，其余节点照常交付。 |
| SF8 已收到 DATA 但 ACK 丢失时，控制中断后仍可试用 SF8 | 同一会话的首个有效 Request 可在预算允许时试用上次交付的 SF，已在模拟无线传输中验证。 |
| 未确认的降档试用在无记录可评估时仍会到期 | 主机策略测试覆盖帧编号期限以及成功计数提前达到上限的情形。 |
| 最后一帧 ACK 时序故障仍保留交付记录，并跳过 ADR 更新 | 主机故障注入。 |
| Gateway 错过某个 Client 的首传接收窗时，另一 Client 的 ADR 可继续更新 | 模拟无线传输和 Gateway 主循环延迟。两个节点均完成交付，其中一个通过重传。 |
| 最后一个 ACK 有时序异常时，已观测的首传丢失仍可用于恢复 | 在模拟无线传输中运行实际状态机，分别使用两个和八个 Client。一个节点达到 SF10，其余固定节点每帧均交付。 |
| 首传窗口内的本地 RX 故障既不作为该节点的丢包依据，也不清除其他节点的记录 | 故障注入中，受本地故障影响的节点保持 SF7，另一节点达到 SF8。 |
| 两次丢失之间的一次交付仍可触发升档试用 | Request SNR 较高时模拟丢失、成功、丢失，下一次 Grant 分配 SF8。 |
| Client 持续发送 Request 时，失败的 SF 试用也会释放预留 | 八节点故障注入中，两个节点的 DATA 在所有 SF 均失败。第三个节点达到 SF10，其余五个节点每帧均交付。 |
| 最后一个 ACK 有时序故障时，已确认的 SF 能超过试用期限继续使用 | 两节点和八节点主机试验在期限后继续交付。另行验证拒绝帧编号不匹配及试用前的回执。 |
| RSSI 较低但交付正常时可维持 SF7 | 双节点对照中，低 RSSI 且交付正常的节点保持 SF7，RSSI 较强但 DATA 丢失的节点达到 SF10。 |
| 采集工具独立保存九路串口的时间戳和哈希 | 模拟串口测试。 |

## 实验 ADR 模型

`python tools/adr_sim.py --seed 42` 对每种场景、丢包率和规则运行 128 组配对试验，
每组 480 帧。假定单个 Client、SF9 控制始终成功、各次发送的干扰相互独立，以及暂定解码曲线。
最终丢包率按最多四次 DATA 发送计算。

| 代表性模型场景 | 固定 SF7 | 交付窗口 | EWMA | Kalman |
|---|---:|---:|---:|---:|
| 20% 独立干扰，高于参考 SF 的时间占比 | 0% | 78.54% | 0.06% | 0.06% |
| 同一场景，最终丢包率 | 0.179% | 0.174% | 0.179% | 0.179% |
| 9 dB 遮挡、10% 干扰，到达参考 SF 的平均时间 | 未达到 | 59.2 秒 | 81.1 秒 | 81.1 秒 |
| 同一遮挡场景，最终丢包率 | 32.196% | 0.618% | 0.802% | 0.802% |
| 同一遮挡场景，每次上报的平均发送次数 | 2.057 | 1.137 | 1.183 | 1.183 |

参考 SF 为达到模型暂定 50% 解码门限的最低 SF。模拟遮挡开始时，所有规则都从 SF7
和清空的策略状态起步。改变策略门限时，模型的解码曲线保持固定。表中的实验规则
高于参考 SF 的时间较少，遮挡后达到参考 SF 也较慢。Request 与 DATA 的 SNR 偏移需通过
匹配条件的现场试验标定。

在同一遮挡场景中，只把策略门限降低 2.5 dB 后，交付窗口、EWMA 和 Kalman 的平均反应时间
分别升至 63.3 秒、92.2 秒和 92.1 秒。三种规则各 128 次均达到参考 SF。
该偏移等于相邻 SF 暂定门限之差。模型假定控制正常，上述主机测试单独覆盖时序故障和其他节点流量。

## 扩展节点容量

空口 v6 调度最多登记 128 个客户端。单射频每帧服务至多八个节点，DATA 占用空口时间增大时可缩小分组。载荷上限为 32 字节，70、84 和 128 个同 SF 节点的服务间隔见[容量表](SCHEDULED_LINK.md#rotating-schedule)。认证会增加开销。例如，128 个 SF10 节点的模型从 645 秒增加到 960 秒。认证帧目前仍处于设计阶段。

5–10 分钟是适宜 SF 分布下的服务间隔目标。交付还需要 SF9 控制覆盖、成功接收 DATA 和相关反馈。记录每个节点最大的交付间隔与超时条件。

1. 使用一台网关与 1、4、8 个物理客户端重复采集。记录首传及最终交付、重传、共享重试池使用、SF 变化、时序故障、重启恢复和逐节点的交付间隔。计算信息年龄时保留采样时间戳。
2. 在相同负载、丢包、控制链路和空口预算下对比固定 SF7、交付窗口、EWMA 与卡尔曼策略。现有模型使用单客户端并假定理想的控制链路。扩展到关联丢包、遮挡与分组轮换后，再评估 70–128 个节点。
3. 实现控制认证和 DATA 加密，再测量帧余量与网关发射占用。部署前测试凭据导入、重启、重放、射频干扰与备份恢复。单网关故障会造成全网中断。
4. 对比同条件的调度与竞争接入方案后，再得出容量结论。记录天线方向图与业务负载。Moxon 的定向覆盖和集中器的并行接收对应不同的部署条件。
